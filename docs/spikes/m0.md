## 2. Spike：TS 7 + orval

**做法**
1. `go run ./cmd/linkspage openapi > web/openapi.json`（OpenAPI 3.1.0，`info.version` 为 `dev`）。
2. `web/orval.config.ts`：`client: "fetch"`、`mode: "split"`，输出到 `web/src/shared/api/gen/`（`linkspage.ts` 和 `model/`），`clean: true`，不依赖 react-query。
3. `src/shared/bootstrap.ts` 直接使用生成的 `getPublicBootstrap()` 和 `Bootstrap` 类型。
4. 用项目里的 TypeScript 7.0.2 跑 `tsc -b --noEmit`（project references：`tsconfig.app.json` + `tsconfig.node.json`）。

**结果**
- orval 8.40.0 生成耗时约 0.8 秒，生成代码在 TS 7.0.2 下类型检查通过，整个 `tsc -b` 约 1 秒。
- 故意写入类型错误（包括对生成类型的误用）后，TS 7 能正确报错，说明检查确实生效。
- `make gen` 连续运行两次，`openapi.json`、`src/shared/api/gen`、`internal/store/dbq` 没有差异（幂等）。
- **没有失败项，所以没有使用文档中的回退方案。**

**踩到的坑**
- orval 间接依赖 esbuild。pnpm 11 遇到未批准的构建脚本会直接报错（`ERR_PNPM_IGNORED_BUILDS`），而不是只警告。处理：在 `web/pnpm-workspace.yaml` 写 `allowBuilds: { esbuild: false }`。esbuild 的二进制来自平台包，不需要 postinstall。
- pnpm 11 默认启用发布冷却期。当天发布的 orval 8.40.0、@vitejs/plugin-react 6.1.2 被 pnpm 自动写进 `minimumReleaseAgeExclude`，超过冷却期后可以删掉这些条目。
- 生成的 `Settings.locales` 类型是 `string[] | null`（Go 的 nil slice）。前端已按可空处理；也可以在 M1 让后端保证非 nil，或给 Huma 字段加 `nullable:"false"`。

**接线**
- `make gen`：sqlc（`sqlc/sqlc:1.31.1` 容器，本机不必安装）→ openapi → orval。
- CI：`go` job 对比 `web/openapi.json`；`web` job 重新运行 orval 并 `git diff --exit-code src/shared/api/gen`。

## 3. Spike：hash CSP 与 304

**curl 校验**（容器，`compose.yaml` + `compose.direct.yaml`）：
- `/`、`/privacy`、`/c/test`、404 页面中的每个内联 `<script>` 和 `<style>` 都计算了 sha256（base64），全部出现在 `Content-Security-Policy` 里。共 3 个内联块：boot 脚本、`lp-critical`、`lp-theme`；`#lp-data` 是 JSON，不需要 hash。
- 模板输出中没有 `style=` 属性。
- 200 带弱 ETag；带 `If-None-Match` 重新请求返回 **304**，CSP 头与 200 **逐字节相同**，body 为空。gzip（`Vary: Accept-Encoding`）下 ETag 相同，304 也成立。
- `/admin/` 使用后台 CSP，同样可以返回 304。404 页面不带 ETag，这是预期行为。

**真实浏览器**（内置浏览器面板，Chromium）：
- 首次加载 `/` 没有 CSP 报错。
- 以 `location.reload()` 重新加载时服务端返回 304（access log 中 `status: 304`），仍然没有 CSP 报错，`securitypolicyviolation` 监听器为空。
- **对照实验：** 用 JS 插入一个内联 `<style>`，监听器捕获到 `style-src-elem`（enforce），控制台也出现报错。由此确认上面的「没有违规」是有效结论。
- Trusted Types 的 Report-Only 策略在整个过程中没有触发上报。
- React 挂载后，`#root` 中的兜底 markup（`.lp-shell`）被替换。`--lp-bg` 和 `--lp-accent` 来自 `<style id="lp-theme">`，body 背景为 `rgb(249,247,241)`。模拟暗色时，`data-appearance="dark"`，背景为 `rgb(17,18,22)`。
- 截图只在会话中留档，没有提交。

## 6. 集成阶段修复的问题

1. **前端和部署两个 builder 都没有产出**（报告为 null，目录不存在）。集成阶段补齐了：`web/` 整个工程，以及 Dockerfile、`.dockerignore`、compose 文件、`deploy/`（init.sh、backup 镜像、CI 脚本）、`config/` 示例、Makefile、`.github/`（CI、release、模板）、renovate.json、README（中英）、CONTRIBUTING.md、SECURITY.md。
2. **后端误报 WARN：** 原来只要 `config.yaml` 里出现 `password_hash` 字样，就会警告「含密码哈希且所有人可读」，被注释掉的示例也会触发。改为检查解析后 `auth.local.users[].password_hash` 是否有值，并补充测试 `TestLoadWorldReadableIgnoresCommentedHashes`。
3. **golangci-lint v2.14.0 报 G304：** 位置是 `internal/provider/providertest/headers.go`（测试辅助函数读取 fixture），已加带说明的 `//nolint:gosec`。

### 6.1 代码审查后的修复（Go / TS / 安全运维三路审查）

**后端**
- 启动流程拆成可测试的 `startupRunner`（`cmd/linkspage/startup.go`）。只有 `store.ErrUnsupportedServer`（PG < 18）、`store.ErrIncompatibleApp`（二进制比 schema 旧）和 `store.ErrMigrationRejected`（SQLSTATE 0A/22/23/42、goose 源错误）会终止进程；查询瞬时失败（如 57P03、连接重置）继续退避重试，连续 5 次失败后改用 ERROR 级别日志。
- 短超时（30 秒）只用于 ping、版本检查、兼容性检查和快照加载；迁移只受服务上下文约束，不会被 5 分钟上限反复回滚。
- 关闭时先取消并等待启动 goroutine，再关闭连接池；收到第一个信号后恢复默认处理，第二次 Ctrl-C/SIGTERM 立即退出。
- `/assets/*` 的 Range 请求不再被 gzip（之前 206 + gzip 的 Content-Range 不对）；HTML 和静态资源始终带 `Vary: Accept-Encoding`，304 与 200 一致。
- `/readyz` 的数据库 ping 结果缓存 1 秒且串行执行，公开探测不会占满连接池。
- CrossOriginProtection 移到中间件链内部：拒绝的请求带请求 ID 和安全头、写访问日志并记 WARN。
- 特权路径访问日志中的 `code`、`state`、`token` 等查询参数改为 `[REDACTED]`。
- 新增 `hsts`（默认 false，仅在 base_url 为 https 时发送 `Strict-Transport-Security: max-age=15552000`），对应 12.4 节。
- 配置：低层（YAML）的 `*_file` 不再覆盖高层（环境变量）的明文值，改为忽略并 WARN；`providers.http_proxy` 打印、序列化、日志中隐去密码；`hash-password` 的提示改为说明 PHC 格式和上限（命令在 M2a 实现）。
- `.secret_key` 通过临时文件 + fsync + `os.Link` 原子创建，并发启动也只会得到同一把密钥；已有文件权限过宽时自动改为 0600，改不了就报错。
- `linkspage healthcheck` 按默认值 → 配置文件 → `LP_SERVER__ADDR` 解析 `server.addr`，监听具体地址时直接探测该地址。
- go.mod 增加 `toolchain go1.26.8`，本地构建不再使用有已知漏洞的 1.26.3 标准库；govulncheck 无告警。

**前端**
- `isBootstrap` 校验公开入口读取的全部字段（`locales`、非空 `defaultLocale`、两套调色板和主题字符串）；嵌入数据无效时回退到 API。
- 加载失败时用 `window.reportError` 上报，保留服务端兜底 markup 并在上方显示提示；渲染异常由 `ErrorBoundary` 接住。
- `?lang=` 的选择写入 `lp_lang`；非默认语言时「返回首页」链接带上 `?lang=`，服务端标题与正文一致。
- 无障碍：语言导航的 `aria-label` 本地化、语言链接显示自称（Intl.DisplayNames）、箭头和计数对读屏隐藏；`notFound` 路由有独立文案，`switch` 恢复穷尽检查。
- 文案目录由编译器保证各语言键一致，另有键一致性测试；`tsconfig.app.json` 的 lib 降到 ES2022，与 Chrome 99 / Safari 15.4 基线一致。
- 新增 boot.js 与 `resolveAppearance` 的一致性测试；Vite 开发服务器注入 boot.js、`/admin/*` 返回后台入口；React 标题的行高和字距与 critical.css 对齐，减少替换时的布局偏移。

**部署与 CI**
- `backup.sh`：循环模式每轮用独立进程执行 `once`，`set -e` 和 `pipefail` 生效；所有产物以流的方式（经 age）写入 `.part`，整条管道成功后才改名；失败时清理 `.part` 且不清理旧备份；先校验 age 收件人。`.secret_key` 和配置只在设置了收件人时备份，配置包只含 `config/` 和 `secrets/admin_*`。
- compose：db、cloudflared、backup 都加了 `no-new-privileges` 和 `cap_drop: [ALL]`（按需 `cap_add`），cloudflared 和 backup 的根文件系统只读；`compose-check.sh` 对此做断言。
- release：构建资产的 job 只有 `contents: read`，用 artifact 交给不检出代码、不安装依赖的 `publish` job（`contents: write`）；所有 checkout 设 `persist-credentials: false`。
- `init.sh`：值经环境变量传给 awk（不再被 `-v` 解析转义），base URL 改为字符白名单。
- 供应链：Renovate 增加 `docker:pinDigests`；CI 下载的 compose v2.20.1 校验 sha256；`packageManager` 带 `+sha512` 校验值（已验证错误的值会被 corepack 拒绝）。
- Dockerfile 的 web 阶段复制 `internal/webui/templates`，Tailwind 的 `@source` 在镜像中和本地看到的文件一致。

## 8. 遗留问题与 M1 跟进

- **语言不一致：** 服务端按 `?lang=` 或默认语言渲染 `<title>` 和 OG；前端还会参考 `lp_lang` 和 `navigator.languages`。M0 已让前端在确定语言后同步 `document.title`（`start.tsx`，有单测），页面标题与正文不再错位。剩下的是无 JS 访问和服务端 HTML 仍用默认语言：M1 让服务端渲染时读取 `Accept-Language`（链接预览爬虫仍看默认语言，见 tech-selection 8.3）。
- **E2E 门禁：** Playwright 的 `securitypolicyviolation` 监听（含 reload 用例）、axe、`browserslist` + stylelint 浏览器兼容检查（8.1、13.2 节）还没有接入 CI，计划随 M1 的门禁一起加入。本次只在浏览器中手工验证。
- **镜像 digest：** Dockerfile 和 compose 的基础镜像目前只按标签固定，Renovate 启用 `docker:pinDigests` 后会提 PR 改成 `@sha256:`。
- **dist 中的 HTML：** `web/dist/index.html` 和 `admin/index.html` 也会被嵌入，但 Go 不会提供它们，只多占几百字节。可以在 M1 让 `make web-dist` 和 Dockerfile 只复制 `assets/` 和 `.vite/`。
- **待实现的命令：** `config/config.example.yaml` 中提到的 `hash-password` 在 M2a 实现。
- **生成代码的可空类型：** `locales` 等字段在生成代码中是可空的，见第 2 节。
- **发布流程：** release.yml 未经实际 tag 验证，首次发布 v0.1.0 时要检查 GHCR 包是否已设为 Public。
- **providers.md 的文档修订：** 第 4 节对 tech-selection.md 5.3 和 5.4 的 4 处修订还没有合入正文。
